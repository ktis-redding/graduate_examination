# 卒業制作

# 1. サービス概要

定例会議の議題に出た残件タスクに対する各自のTODOを明確化、
フォローアップの推進・達成度を可視化するサービスです。

## 2. このアイデアはどこから生まれたか

### 2-1. きっかけとなった体験・感情

このアイデアの元になったのは、毎週定例会議を開いている中で、
残案件(TODO)の共有・フォロー内容・達成度の可視化が、
議事録だけでは不十分だと感じていました。
議事録＋専用アプリで案件管理が強化できると考えています。

### 2-2. なぜそれが「気になった」のか

「今」の状態は議事録で記録・共有できていますが、
「後」のフォローは個人の裁量に任せられている部分が大きく、
会議参加者によってフォロー・達成度も差が出ています。

## 3. 課題の整理（表面的になっていないか）

### 3-1. 表に見えている困りごと

何を誰がいつまでにするのかという点が、
共通認識として参加者に浸透していない。
または認識していても取り組みに個人差がある。
それにより次の会議でも前回の議題から進みが悪く、
同じ事を繰り返し何度も話す機会が多い。

### 3-2. 本当に解決したい課題は何か

本当に解決したい課題は以下です。
「残案件を個人の裁量に任せず、
チームとして進めて行く」

## 4. 想定ユーザーについて

### 4-1. 想定しているユーザー

社内会議参加者

### 4-2. 自分とユーザーの距離

自分及び社内メンバー

### 4-3. 実際に使われる可能性について(需要・存在確認)

最初に使ってくれそうな人は現在議事録を取っている方。

## 4-4. ユーザーがサービスを導入して利用するまでのイメージ(導入・継続の流れ)

このサービスは、私と議事録係が主体となり会議中・後に使用します。
会議中・後に管理者として私のみ登録・記入等をしていきます。
次の会議で私が会議参加者に進行状況をヒヤリングし、
課題の達成・未達成・期限変更をアプリに入力していきます。
導入後半年間はブラッシュアップの期間として改良を重ね、
それ以降は会議参加者が会議中・後に自ら書き込むイメージです。

## 5. 既存サービス・競合調査

### 5-1. 似たサービスの調査

- サービス名：Notta
- URL：https://www.notta.ai/
- 議事録録音→TODOリスト自動生成→役割分担・期限記入

### 5-2. それでも自分が作りたい理由

会議参加者の曖昧なニュアンス表現もくみ取りたいので、
自らポイントを咀嚼してアプリに記入する方がいい。

### 5-3. 差別化を「体験価値」で表現する
会議参加者全員が、会議で始まった瞬間に、会議の方向性が定まり助かります。
また会議参加者全員が、会議後に会議内容を見返す瞬間に、やるべき事の方向性が定まり、
行動計画が立てやすくなり助かります。

## 6. このサービスで提供したい価値

### 6-1. ユーザーの変化

視覚化による課題の明確化と達成状況を共有できるので、
会議の進行またはその前の準備が早く・深くなると期待する。
またチームにおける貢献度を判断してもらう良い機会になる。
チーム全体としては特定の人にジョブが集中するのを避けられる。

### 6-2. 価値を一文で表す

「残案件を個人でなくチームで進めて行く」

## 7. このアプリで実現すること

### MVPで作る機能
1.会議参加者メンバー登録
2.議題ごとにTODOを登録
3.担当者・期限を設定
4.TO DO全体を表示
5.次の会議で前回TODOの達成状況を確認
6.内容・期限・達成/未達成を編集
7.達成済みTODOを非表示
*期限と達成日の記録は本リリース時に追加予定

## 8. このアプリの懸念点とその対策

TODOが達成されないまま追加されていき、
優先順位が分からなくなる可能性がある。
対策として期限切れ案件をリスト上部に表示する。

## 9. 今後の展開・発展の方向性

現状の課題把握・解決のケーススタディをストックしていき、
今後の類似案件の際にAIが助言してくれる仕組みにしていく。

### 観点（すべて答えなくてOK）

続ける事で「達成」の蓄積が社内評価になる

### 今考えている発展案

- 機能追加の方向性：社内データベース化→AIによる提案
- UI・体験の改善：文字主体→グラフィック主体へ
- 機能以外の工夫：スマホ対応

## 10. 技術スタック（手段としての技術）

### 10-1. 使用予定の技術

- フレームワーク：React, Next.js
- DB：PostgreSQL
- デプロイ先：Vercel ＋ Supabase
- 使用予定ライブラリ：
1.TODO 画面一覧(TanStack Table)
2.TODO 登録・編集フォーム(React Hook Form + Zod)
3.画面アイコン -編集,削除,検索等- (Lucide React)
4.期限管理-期限切れ,日付け等- (date-fns)

### 10-2. 技術選定の比較検討

ITリテラシーが高くない職場なので、
シンプルで直感的なシステムにしたい。
この技術であれば上記を満たしていると思えました。
またこのアプリの使用人数は5~10人程度想定なので、
AWSのような大規模クラウドは必要ありません。

### 10-3.キャッチアップ不足の懸念
フォーム、状態管理、ルーティング、API連携などの基本操作は、
カリキュラムで触れたのと少し調べた程度で習熟度は低いです。
アプリ製作は初めてで上記基本操作含めトライアンドエラーで進めます。

キャッチアップ不足の段階では以下の懸念点があります。
1. 初めてのシステム構築で技術的な不明点が多い
   システム構築の経験が無いので不明点が多く、バグの対処が適正にできるかの懸念がある。
2. **Issueの見積もりが難しい**
   各工程にどれ位の時間と労力を要するのか分からず、開発期間の見通しをクリアにするのが難しい。
